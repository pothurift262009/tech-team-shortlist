Then I built a decision tree that explains every one of the 24 invite decisions. Candidate IDs are anonymised by score rank. The tree is my model of the process, not a confirmed rule.

The answer: a 3-question decision tree explains all 24 decisions

1. Is the GitHub score at least 18.5? (in practice, a rounded score of 19 or more) If not, no invite. This removes 16 of 24.

2. Has at least one of your recent repos been starred by someone? If yes, invite.

3. If not, have you put a licence on at least 3 recent repos? If yes, invite. If not, no invite.

In plain words: clear the score bar, then show one sign your work is ready for others. That sign is either someone valued it enough to star it, or you published it properly with a licence. The top scorer who was left out (C02, 24.09) has neither.

Method and caveats

How the as-of date works. Data was pulled from the GitHub API on 25 Sep 2026, using the collection code from githubscore.py. For each date, I rebuilt what the script would have seen on that day:

  • Repos created after the date are dropped, and the 18-month window and account age are counted back from the date.
  • Each repo is read at its last commit on or before the date. This decides whether it had tests, a README or a licence at that point.
  • Repos untouched since the date use the same GitHub API checks as the script.
  • CI, tags, releases, PRs, issues and reviews count only if they were created by the date.
  • Followers and stars can only be seen as they are today, so the tree uses today's star counts. The starred repos all existed by 8 Sep, but GitHub didn't let me read when each star was added.
  • As a check, rebuilding "today" this way lands within about half a point of the script's own result for every candidate.

The last date is 8 Sep 2026, before the shortlist. Across 25 Aug – 8 Sep the ranking of the top 8 never changes, so the conclusions don't hinge on the exact day.

Change from my first version: it had an "unmerged PR penalty" rule. The rebuilt data shows no one in the top 9 had any PR to someone else's repo by 8 Sep, so the tree replaces that rule with stars and licences.
